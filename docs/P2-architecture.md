# P2 实施约定与数据生命周期

用户最新要求：**UI 与 0.1.0 保持一致，只优化内核，不重新设计界面。**
这是后续界面工作的约束，优先于之前关于 P2 菜单或控件的实施决策。

普通预览复用 0.1.0 原始 Text 标签/消息绘制，保留绿色己方气泡、白色对方消息、
日期分隔、34px 圆形头像、引用灰底、撤回灰条、字体和间距。多选复用原来的灰色圆形
复选框、整行淡蓝底和左对齐内容。主界面双栏比例及导出/全选/日期/下一步/取消位置
不变，不增加菜单栏。P2 功能放到导出按钮、标题、预览空白的右键菜单与快捷键。
单会话导出恢复原完成提示，批量队列仅从明确的批量入口打开。

底层仍是有界可视区控件池，每行装载经典渲染器；源分页、后台解码、租约、缓存和
搜索保持。需要改变外观时必须有用户明确的新要求，不能以性能优化为由换皮。

- Repository 以 mode=ro 打开解密副本；内存 TEMP 定位表只存会话/时间/消息 ID/行号。
  稳定游标为 `(ts,msg_id,rowid)`，rowid 仅处理重复键，不改变公开消息 ID；正文按页解析。
- 搜索默认 SQLite 内存 FTS，关闭数据源/退出时销毁；不默认产生持久正文索引。
- 无 FTS5 trigram 时用 instr 对 casefold 正文进行字面包含匹配，避免把用户的 %/_
  解释为 SQL 通配符；高级正则使用 regex 的真实超时，防止复杂表达式长时间占用线程。
  历史关键词单独本地保存需显式启用，提供清空。搜索结果、队列、增量和归档统一复用
  Message/Segment 与导出管线。
- 异步工作只通过队列将结果交给 Tk 主线程；每次切换数据源/会话有 generation。
  任务持有数据源租约，刷新/切账号不会清理仍被使用的解密副本；最后租约结束才清理。
- 增量目录显式含明文消息快照与 manifest，只有用户启用增量才创建；普通三格式仍不
  增加额外文件。先验证旧文件哈希与消息游标，冲突停止，完整临时目录成功后原子替换。
- 队列恢复只存任务参数/状态与账号标识，不存正文；恢复前校验账号并由用户确认。
  归档/导出本身含敏感正文，文档明确告知，不上传。
- 缩略图仅保存在应用 cache，以内容哈希命名，LRU 上限可配置、可清空；内存解码池与
  可视区有界。媒体重试只重新扫描本机，不自动访问 CDN。
- 加密归档、库合并、计划导出属于任务书可选项；插件明确不在本阶段。范围与可选项
  实施状态必须在最终验收表逐条记录，不以泛称“P2 完成”掩盖未验证项。
