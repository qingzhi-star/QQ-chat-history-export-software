# 版本与发布规则

版本唯一来源为 `pyproject.toml` 的 `project.version`。修改后运行
`python tools/build_release.py --sync-version`，构建会验证 README，并把同一版本注入
运行时 METADATA、PE 文件版本、安装包/绿色版文件名和发布标题。

- 每个任务一个提交并立即推送；普通提交、测试和文档修订不自动涨版本。
- P1+ 的修复与发布工程收尾：`0.1.1rc1` → 验收后的 `0.1.1`。
- P2 的搜索、批量、增量、归档等新增能力：`0.2.0rc1` → 验收后的 `0.2.0`。
  本轮 T11 已进入 `0.2.0rc1`，包含全部 P1+ 修复；无需先给未验收的 `0.1.1rc1`
  打稳定标签。任务实现完成与正式版验收通过分别记录。
  用户要求恢复原 UI 后，下一候选为 `0.2.0rc2`；这是候选版修订，不新增功能版本。
  追加头像/文件名/系统图片查看器修订进入 `0.2.0rc3`，沿用候选序列。
- 同一候选版发现问题后递增 `rcN`，已发布的标签和资产不可覆盖。
- 后续补丁修复递增第三段；新增功能递增第二段。0.x 阶段的不兼容改动也递增第二段，
  并写迁移说明；1.0 需单独稳定性验收。
- Git 标签严格为 `v` + 包版本，例如 `v0.2.0rc1`。候选版标记 pre-release，正式版不标。
  历史 `v0.1.0-pre.2` 保留，不作为新标签模板。
- Electron Release 标题为 `绮录QQ聊天记录导出软件 v<版本>`（旧 Tk 为 `qqexport v<版本>`）；只上传同版本安装包和便携版。源码使用 GitHub
  自动生成的源码包。SHA256SUMS/清单作为构建证据和正文，不混入额外分发资产。
- 未完成验收不去掉 `rcN`；SKIP、未运行、待真机验证均不算 PASS。

版本号不跟任务号、提交数量或日期联动。源码/依赖/工具链指纹与资产 SHA-256 用于精确
追踪某次构建，不能用“版本相同”代替产物一致性验证。

Electron 桌面端作为 0.x 阶段的新架构，递增第二段为 `0.3.0rc1`。
Python 元数据/源码显示 `0.3.0rc1`，npm 按 SemVer 表示为 `0.3.0-rc.1`，
二者是一份版本的格式映射，不是两套独立版本。构建脚本校验一致性；PE 使用四段数字。

`0.3.0rc2` 修正真实账号发现参数，并完成 Electron 内置 P2 工具迁移，
替换 rc1 的经典窗口入口。沿用 0.3.0 候选序列；桌面交付按版本命名，不复用旧候选。

`0.3.0` 为用户明确要求的首个 Electron 正式版，范围按 Windows 11 x64 验收。
使用独立的 Electron 构建/冒烟/发行门，不复用旧 Tk 包和旧证据。
真实 PDF 改为 Electron 内置 Chromium；主界面导出无需系统 Edge。
Windows 10 和其他架构没有填写 PASS，不列入本版已验证支持范围。

`0.3.1` 为 `0.3.0` 的补丁：快照忙重试、刷新与消息读取并行、解析页有界缓存、
断网头像请求隔离，以及用户指定的“更多功能”固定标题/右上关闭按钮。
主界面与既有交互保持不变。修复递增第三段，不覆盖已发布的 `v0.3.0`。
