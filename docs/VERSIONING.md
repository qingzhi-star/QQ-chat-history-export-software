# 版本与发布规则

版本唯一来源为 `pyproject.toml` 的 `project.version`。修改后运行
`python tools/build_release.py --sync-version`，构建会验证 README，并把同一版本注入
运行时 METADATA、PE 文件版本、安装包/绿色版文件名和发布标题。

- 每个任务一个提交并立即推送；普通提交、测试和文档修订不自动涨版本。
- P1+ 的修复与发布工程收尾：`0.1.1rc1` → 验收后的 `0.1.1`。
- P2 的搜索、批量、增量、归档等新增能力：`0.2.0rc1` → 验收后的 `0.2.0`。
  本轮 T11 已进入 `0.2.0rc1`，包含全部 P1+ 修复；无需先给未验收的 `0.1.1rc1`
  打稳定标签。任务实现完成与正式版验收通过分别记录。
- 同一候选版发现问题后递增 `rcN`，已发布的标签和资产不可覆盖。
- 后续补丁修复递增第三段；新增功能递增第二段。0.x 阶段的不兼容改动也递增第二段，
  并写迁移说明；1.0 需单独稳定性验收。
- Git 标签严格为 `v` + 包版本，例如 `v0.2.0rc1`。候选版标记 pre-release，正式版不标。
  历史 `v0.1.0-pre.2` 保留，不作为新标签模板。
- Release 标题为 `qqexport v<版本>`；只上传同版本安装包和绿色版。源码使用 GitHub
  自动生成的源码包。SHA256SUMS/清单作为构建证据和正文，不混入额外分发资产。
- 未完成验收不去掉 `rcN`；SKIP、未运行、待真机验证均不算 PASS。

版本号不跟任务号、提交数量或日期联动。源码/依赖/工具链指纹与资产 SHA-256 用于精确
追踪某次构建，不能用“版本相同”代替产物一致性验证。
