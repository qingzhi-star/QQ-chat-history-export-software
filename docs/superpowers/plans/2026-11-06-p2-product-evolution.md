# P2 任务书：功能扩展与性能架构

**文档版本：** 1.0  
**日期：** 2026-11-06  
**状态：** 提案，待确认后执行  
**前置：** P1+ 稳定性与发布工程完成；主界面已定稿，P2 变更需单独评审。  
**关联文档：** `2026-11-06-p1plus-stabilization.md`、P1 设计与兼容矩阵。

> P2 的目标不是“堆功能”，而是在不破坏本地隐私、不改变只读原则的前提下，
> 把工具从“单次导出器”扩展为“可检索、可批量、可增量维护的本地聊天备份工具”。
> 任何 P2 功能都必须先满足 P1+ 的数据安全与原子性约束。

---

## 1. 目标与边界

### 1.1 目标

1. **找得到**：按关键词、发送者、时间、消息类型检索本机聊天。
2. **批量管**：一次导出多个会话/全部会话，有队列、进度、失败重试。
3. **增量维护**：对已有导出只追加新消息，避免每次全量重导。
4. **内容更完整**：合并转发、语音、文件、卡片、红包、通话等类型的可见降级。
5. **规模可用**：十万级消息、数万图片下仍可流畅浏览与导出。
6. **可迁移**：提供带清单与校验和的归档格式，便于长期保存。

### 1.2 非目标

- 不提供云端同步、账号系统、远程访问或在线分享。
- 不绕过 QQ 服务器权限；不恢复服务器已删除且本机未缓存的内容。
- 不修改原始 QQ 数据库，不读取 QQ 进程内存（P0 边界不变）。
- 不做跨平台客户端；仍以 Windows 10/11 x64 为主。
- 不做聊天记录编辑、伪造、批量删除 QQ 数据等破坏性功能。

## 3. 功能需求

优先级：P0 为 P2 首批；P1 为第二批；P2 为可选。

### 3.1 搜索与筛选

| ID | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| P2-F01 | P0 | 当前会话内关键词搜索 | 输入关键词后返回匹配消息列表，点击跳转并高亮 |
| P2-F02 | P0 | 全库搜索 | 跨会话搜索，结果含会话、发送者、时间、摘要 |
| P2-F03 | P0 | 筛选器 | 按发送者、消息类型、日期范围组合过滤 |
| P2-F04 | P1 | 搜索历史/最近关键词 | 仅本地保存，可清空 |
| P2-F05 | P1 | 正则/精确匹配开关 | 默认普通包含；高级模式明确提示 |
| P2-F06 | P1 | 搜索结果导出 | 将当前结果集导出为 TXT/HTML，复用 P1+ 管线 |
| P2-F07 | P2 | 搜索结果高亮与上下文 | 显示前后各 1 条上下文 |

**隐私约束：** 搜索索引只存本机；默认不持久化正文到独立索引文件。若启用持久
FTS，必须提供“清除索引”入口，并在 README 说明索引含聊天正文。

## 4. 性能与规模目标

以 10 万条消息、2 万张图片、50 个会话为参考规模；中等配置
（4 核 / 16GB / SSD）。

| ID | 指标 | 目标 | 方法 |
|---|---|---|---|
| P2-P01 | 会话首屏 | ≤ 300 ms | 从点击到首屏可读 |
| P2-P02 | 滚动 | ≥ 55 FPS | 10 万条列表滚动采样 |
| P2-P03 | 内存峰值 | ≤ 500 MB | 10 万条 + 缩略图 |
| P2-P04 | 会话内搜索 | ≤ 200 ms（10 万条） | 本地索引/扫描基准 |
| P2-P05 | 全库搜索 | ≤ 500 ms（50 万条） | FTS 基准 |
| P2-P06 | 打开会话 | ≤ 800 ms | 首次分页读取 |
| P2-P07 | 批量导出 | 50 会话排队不冻结 UI | 主线程阻塞 ≤ 100 ms |
| P2-P08 | 增量导出 | 100 条新消息 ≤ 5 s | 固定基准 |
| P2-P09 | 缩略图加载 | 首屏 ≤ 200 ms | 懒加载 + 缓存 |

超预算必须记录数据、瓶颈、取舍与后续任务。

## 5. 架构方案

### 5.1 数据访问层

- 新增 `MessageRepository`：按会话、时间、ID 分页读取，禁止一次性 `list()` 全表。
- 查询使用稳定游标 `(ts, msg_id)`；实时追加用同一游标，避免重复/漏读。
- 搜索索引与 QQ 源库分离：应用数据目录下独立 SQLite/FTS；源库始终只读。
- 所有路径、账号、正文写入索引前评估隐私；提供清除与重建。

### 5.2 预览虚拟化

- 将右侧预览从 `Text` 迁移为虚拟化行列表（Canvas + 可视区行复用），
  每条消息一个视图模型；只创建可视区与缓冲区的行控件。
- 图片懒加载：先占位，滚动进入视口后解码缩略图；原图按需加载。
- 复用 P1+ 的多选行模型，避免“普通视图/多选视图”两套渲染分叉。
- 保留现有视觉：头像、气泡、时间、图片、回复、撤回提示。

### 5.3 搜索

- 首选 SQLite FTS5（若 Python 自带 SQLite 不支持则降级 `LIKE` + 分页）。
- 索引字段：会话 ID、消息 ID、时间、发送者、正文；不索引图片二进制。
- 增量索引：启动时补齐新消息；失败可重建。
- 结果跳转：虚拟列表定位到消息 ID，高亮关键词。

### 5.4 导出引擎

- 从“单会话同步函数”升级为 `ExportJob` 队列：任务、状态、取消、重试。
- 增量导出使用清单 + 尾消息游标；TXT/HTML 追加，PDF 重建。
- 归档使用 ZIP + manifest + checksums；写入临时文件后原子改名。
- 批量导出复用 P1+ 原子目录与清理策略。

### 5.5 媒体缓存

- 缩略图缓存目录位于 `%LOCALAPPDATA%\QQExport\cache`，按内容哈希命名。
- LRU 上限（默认 2GB，可配置）；退出/清理任务删除过期项。
- 不把源库路径、账号、聊天正文写入缓存文件名。
- 缺失媒体清单只记录消息 ID、类型、时间、会话显示名（脱敏可配置）。

## 8. 数据与隐私约束

1. 源 QQ 数据库、WAL、伴随库始终只读；所有解密在工作副本进行。
2. 搜索索引、缩略图缓存、归档均可能含敏感内容，必须提供清理入口与文档说明。
3. 不上传任何内容；不接入第三方分析/崩溃上报。
4. 批量/增量导出失败不得覆盖已完成产物；临时文件必须可识别和清理。
5. 归档加密若实现，必须使用成熟 KDF（Argon2id/scrypt/PBKDF2）与 AEAD；
   密码不写入配置或日志。
6. 任何“修复/重建”操作必须先备份清单或提示用户，不得静默删除旧数据。

## 9. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 虚拟化重写引入回归 | 预览/多选错位 | 分阶段迁移、双视图对照、视觉快照测试 |
| FTS 索引含正文 | 隐私面扩大 | 默认内存索引、持久化需显式开启、可清除 |
| 增量导出语义复杂 | 重复/漏消息 | 清单 + 游标 + 前后校验，冲突转全量 |
| 大图片解码卡顿 | 滚动掉帧 | 缩略图、懒加载、后台解码、缓存上限 |
| QQ 版本变化 | 解析/搜索字段失效 | 版本探测、降级、兼容矩阵、真实样本回归 |
| 归档格式长期性 | 未来打不开 | 版本化 manifest、纯 HTML 兜底、校验和 |
