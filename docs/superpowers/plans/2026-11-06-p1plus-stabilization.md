# P1+ 任务书：稳定性、导出正确性与发布工程

**文档版本：** 1.0  
**日期：** 2026-11-06  
**状态：** 提案，待确认后执行  
**前置基线：** P1 消息解析与 TXT/PDF/HTML 导出已完成；GUI 多选与实时预览已定稿；
当前预发布版本 `v0.1.0-pre.2`。

## 1. 目标

P1+ 不追求增加新的大功能，目标是把现有“能用”的产品做成“可长期发布”的产品：

1. **导出正确**：所选消息、顺序、名称、图片、文件、回复、撤回提示在
   TXT/PDF/HTML 三种格式中语义一致。
2. **失败可控**：任何导出失败都不留下半成品、不覆盖旧产物、不残留明文。
3. **界面稳定**：加载、切换、实时追加、进入/退出多选不串消息、不跳位置、
   不冻结；用户操作有明确反馈。
4. **发布可复现**：同一提交能重复构建出可运行的安装包和绿色版，版本号、
   README、Release 资产一致。
5. **性能有底线**：明确并验证启动、预览、滚动、导出的时间与内存预算。

### 1.1 非目标

- 不新增搜索、批量导出、归档格式等 P2 功能。
- 不改动已定稿的主界面布局与视觉风格；只修复缺陷和补充必要状态提示。
- 不承诺恢复服务器端已过期、且本机未缓存的图片/文件。
- 不增加云端服务、账号登录、遥测或自动上传。
- 不支持非 Windows 平台。

## 2. 用户与关键场景

| 角色 | 场景 | 期望 |
|---|---|---|
| 普通用户 | 备份一段私聊 | 选会话、勾选、导出 PDF，图片完整 |
| 群聊用户 | 导出某日期范围 | 日历选择后只导出范围内消息，格式正确 |
| 长期用户 | 消息很多、图片很多 | 打开不卡，滚动顺畅，导出有进度 |
| 谨慎用户 | 数据敏感 | 不上传、不残留明文、失败不破坏旧文件 |
| 维护者 | 发新版本 | 一条命令构建、测试、发布，资产可追溯 |

## 4. 性能预算

以下为本机中等配置（4 核 CPU / 16GB 内存 / SSD）目标，不是硬性营销指标。
每次发布前用固定合成数据或脱敏真机数据测量，并在任务记录中保存结果。

| ID | 指标 | 目标 | 测量方法 |
|---|---|---|---|
| P1P-P01 | 冷启动到可交互 | ≤ 2.5 s | 进程启动到会话列表可点击 |
| P1P-P02 | 账号识别与会话列表 | ≤ 2.0 s（100 会话） | 日志时间戳 |
| P1P-P03 | 首屏预览 | ≤ 500 ms | 选中会话到首屏可读 |
| P1P-P04 | 滚动帧率 | ≥ 55 FPS（1 万条） | 滚动录制/采样 |
| P1P-P05 | 多选切换 | ≤ 50 ms/行 | 事件到重绘完成 |
| P1P-P06 | 内存占用 | ≤ 400 MB（1 万条+200 图） | 任务管理器/psutil 峰值 |
| P1P-P07 | 纯文本导出 | 1 万条 ≤ 3 s | 固定数据基准 |
| P1P-P08 | 带图 PDF 导出 | 1 万条 ≤ 30 s | 固定数据基准 |
| P1P-P09 | UI 阻塞 | 单次主线程任务 ≤ 100 ms | 任务切片/日志 |

超预算时必须在任务记录中解释原因、影响和后续优化项，不得静默放宽。

## 5. 技术方案

### 5.1 导出管线

- 引入统一 `ExportJob`：消息选择 → 格式化计划 → 临时目录 → 原子替换。
- 三种格式共享同一 `selected_messages` 快照，禁止各分支重新查询。
- TXT/HTML/PDF 各自由纯函数生成；PDF 只从已生成的 HTML 打印，避免语义分叉。
- 目标目录替换使用同卷临时目录 + `os.replace`/目录交换；失败保留旧目录。
- 导出结束统一清理临时目录与解密副本。

### 5.2 GUI 任务模型

- 所有数据库读取、头像/图片解码、导出均在后台线程；Tk 主线程只做 UI 更新。
- 每个异步任务带 generation/token；旧任务结果丢弃。
- 多选使用独立行列表，避免 Text 重排导致的位置漂移；图片保留，按需解码。
- 实时追加使用队列 + 批量刷新；用户离开底部时暂停自动跟随。
- 统一错误对象与脱敏日志；UI 只显示简短原因。

### 5.3 发布工程

- PyInstaller `onedir` 作为绿色版标准结构；启动器负责 Tcl/Tk 路径修正。
- Inno Setup 当前用户安装；安装目录、快捷方式、卸载项固定。
- 版本来源单一：`pyproject.toml` 读取，安装脚本/README/Release 自动同步。
- CI：Windows 3.12/3.13/3.14 测试 + 隐私巡检；打包与安装冒烟在发布前本地或专用 job 执行。

## 7. 验收门

P1+ 完成需同时满足：

1. P0 功能需求全部通过；P1 需求无未解释缺口。
2. Windows 3.12/3.13/3.14 测试全绿；隐私巡检通过。
3. 导出一致性矩阵：TXT/PDF/HTML × 私聊/群聊 × 有图/无图/文件/回复/撤回。
4. 失败注入：磁盘满、权限拒绝、取消、进程中断后无半成品、无明文残留。
5. 性能基准达到或解释偏差；UI 无 >1 s 冻结。
6. 安装包与绿色版在含空格路径实机启动；版本一致。
7. README、免责声明、Release 说明与资产匹配。

## 8. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| QQ 版本升级改表/字段 | 解析失败或漏消息 | 版本探测、未知字段降级、兼容矩阵、真实样本回归 |
| PDF 引擎差异 | 排版/分页变化 | 固定 HTML/CSS、快照测试、PDF 文本层校验 |
| 图片缓存缺失 | 导出缺图 | 明确占位、提示先在 QQ 打开、P2 做缓存恢复 |
| 临时明文泄漏 | 隐私事故 | 同卷临时目录、finally 清理、启动扫描、隐私巡检 |
| 打包路径/Tcl 问题 | 启动失败 | 启动器修正、含空格/中文路径冒烟、绿色版结构校验 |
| 长任务冻结 UI | 体验差 | 后台线程、分片、取消、进度 |
